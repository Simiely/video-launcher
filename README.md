# video-launcher · 视频方案启动器

> 一个窗口管住本地三套视频 AI 方案：**拉起 ComfyUI 服务 → 选输入 → 开跑**。
> 纯 Python 标准库实现（Tkinter，深色 UI 全自绘），零第三方依赖；源码可直接运行，也可打包成单文件 exe。

## 它解决什么

本地部署的视频放大 / 生成方案分散在多个目录、十几个 `.ps1` 里，每次都要手开终端、记参数、盯日志。本启动器把「启动服务 + 挑输入 + 传参 + 实时看日志」收进一个 GUI：

| 能力 | 干什么 | 背后调用 |
|---|---|---|
| FlashVSR 放大 | 视频放大（快） | `video-upscale-deploy/02-FlashVSR/批量放大.ps1` |
| SeedVR2 放大 | 视频放大（画质优先，音轨自动回接） | `video-upscale-deploy/03-SeedVR2/批量放大.ps1` |
| MiniMax H3 生成 | 文生视频 + 音画同出 | ComfyUI 服务 + 网页工作流（参数在网页里调） |

## 界面（v1.2.5 深色控制台 · 2×3 网格）

```
┌──────────┬──────────────────────────────┬──────────────────┐
│ 左栏      │ 中栏                          │ 右栏              │
│ 视频启动器 │ ┌──────────────────────────┐ │ ● ComfyUI 服务    │← 状态 + 版本·显存
│ FlashVSR │ │ FlashVSR 放大     2x/3x/4x│ │   http://127.0.0.1 │← 地址
│ SeedVR2  │ │ 输入 / 模式 / 倍数 / 格式  │ │ [启动][打开网页][停止]│← 三按钮
│ MiniMax  │ │ [       运行放大       ]  │ │ ────────────────  │
│ ──────── │ └──────────────────────────┘ │ 选择 / 加载工作流  │← 下拉 + 加载 .json
│ 设置      │                              │  · 节点详情 / 推送 │
│ 配置项…   │       （上排高度＝内容实测，    │                   │
│ 打开输入  │        剩余高度全给下排日志）   │                   │
├──────────┴──────────────────────────────┴──────────────────┤
│ 运行日志（横跨中栏 + 右栏，约 25 行）                          │
│  · 按类别着色（成功绿 / 工作流青 / 警告琥珀）                  │
│  ─────────────────────────────────────────────────────────  │
│  任务进度 65%                                                │
└──────────────────────────────────────────────────────────────┘
```

- **2×3 网格**：上排＝左（导航 + 设置）/ 中（引擎参数）/ 右（服务 + 工作流）；下排＝一整条**运行日志，横跨中栏 + 右栏**；左栏跨两行、通高
- **上排高度按内容实测、剩余全给日志**（v1.2.5）：上排不再抢高度的结果是日志文本区从 84px（约 4 行）变成 **310px（约 25 行）**
- **设置常驻左栏下方**（v1.2.3 起）：配置项只读展示 + 每项右侧「打开」；不再点导航到中栏单独刷出一页。窄栏下每项为「标签 + 值」两行
- **引擎切换只有左导航一个入口**（v1.2.3 去掉了中栏那排重复的切换按钮，v1.2.5 又去掉了「引擎 · 由左侧导航切换」小标题），点谁就重绘中栏引擎卡
- 窗口 1260×960（最小 1040×940），并按屏幕可用区夹住 —— 保证引擎卡与工作流卡的按钮都不落到折叠线以下，也不会比屏幕还高
- 配色：背景 `#15171c` / 卡片 `#232730` / 蓝 `#4a9eff` / 紫 `#b389f0` / 青 `#34d3b0`，圆角 12px 自绘卡片与柔和阴影
- 设计蓝本见分支 `ui-redesign` 的 `redesign/video_launcher_sidebar.html`
- 服务状态（圆点 / 「运行中」徽标 / 版本 / 显存）每 5 秒刷新；服务未运行时显存退回 `nvidia-smi` 读显卡
- 日志按类别着色（成功绿 / 工作流青 / 警告琥珀），并从输出里解析 `x/y` 或 `n%` 驱动右下进度条
- **子进程一律不弹黑窗**（v1.2.5）：exe 是无控制台程序，所有子进程都带 `CREATE_NO_WINDOW`，不会 5 秒闪一次黑窗
- **崩溃有据可查**（v1.2.5）：万一未捕获异常，会写一份 `崩溃日志.log` 到程序同目录（exe 则写在 exe 旁边）

## 环境要求

- Windows + Python **3.12+**（本机实测 3.13 / 3.14 打包）
- **零第三方依赖**：只用标准库（`tkinter` / `subprocess` / `threading` / `queue` / `urllib`）
- 需要已有一套本地部署（默认路径见下表），或用 `启动器配置.json` 指到你自己的路径

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `comfy_dir` | `C:\AI\ComfyUI` | ComfyUI 底座目录 |
| `comfy_py` | `C:\AI\ComfyUI\.venv\Scripts\python.exe` | 底座使用的解释器 |
| `deploy_root` | `C:\AI\video-upscale-deploy` | 批量放大脚本所在仓库 |
| `ffmpeg_dir` | `C:\AI\ffmpeg\bin` | 显式前置到子进程 PATH，不依赖注册表 |
| `input_dir` | `E:\VideoUpscale\input` | 素材目录 |
| `output_dir` | `E:\VideoUpscale\output` | 成品目录 |
| `comfy_url` | `http://127.0.0.1:8188` | ComfyUI 服务地址 |
| `log_dir` | `<程序目录>\logs` | 日志落盘目录（见「关于运行日志」） |
| `log_to_file` | 未设置（= 关闭） | 置 `true` 后把日志区内容同时写入 `log_dir` |


## 源码结构（v1.2.8 起为三文件）

| 文件 | 说明 |
|---|---|
| `视频方案启动器.py` | 配置 + 业务逻辑 + 界面装配（PyInstaller 入口） |
| `ui_kit.py` | 深色自绘控件库 + 设计令牌（**不 import 业务代码**） |
| `运行时.py` | 与界面无关的运行时支撑：子进程"不弹黑窗"标记 / 崩溃落盘 / 绕代理 HTTP / **日志行解析与清洗**（ANSI 剥离、进度、级别、着色分类）/ **日志落盘**（`LogFile`、`NoopLog`）（**不 import 业务代码，也不 import tkinter**） |

> 按 `AGENTS.md`「按阈值拆分」：单文件逻辑行超过 pylint 默认上限（1000）时才拆。`ui_kit.py` 是 v1.2.0 抽的，`运行时.py` 是 v1.2.5 抽的，v1.2.6 把日志行解析也归了进去（当时主文件到 1001，拆完回到 986）；v1.2.8 的落盘实现同样放 `运行时.py`（主文件 994，**余量只剩 6 行 —— 下一个功能前必须先拆主文件**）。依赖单向：`视频方案启动器.py` → `ui_kit.py` / `运行时.py`。

## 关于运行日志（v1.2.6 实测口径，v1.2.8 加落盘）

日志区有三类来源，**只有本程序启动的服务才有日志可读**：

| 来源 | 日志区里长什么样 |
|---|---|
| 本程序自身 | `[服务] ...` / `[工作流] ...` / `[队列] ...` |
| **由本程序「启动服务」拉起的** ComfyUI | `[ComfyUI] ...`（stderr 已并进同一根管道，逐行实时） |
| 批量任务（PowerShell） | `════ ▶ <任务名>` 之间的输出 + 结束时的 `■ ... rc= / 用时` |

- **已经在外部（自己的终端 / 别的窗口）跑起来的 ComfyUI，日志不会出现在这里**：本程序探测到服务活着就直接返回，那些输出绑在别人的终端上，本程序没有句柄。想在日志区里看 ComfyUI 日志，就用「启动服务」让本程序把它拉起来。
- 显示前会做三件事：剥掉 ANSI 转义码（终端色彩码在 Tk 里会显示成方块）、按权限级别上色（`[ERROR]` 红 / `[WARNING]` 黄）、把行里的进度解析到进度条。日志区最多保留 2000 行，超出自动裁掉最旧的。

### 让日志"留得下来"：日志落盘（默认关闭）

日志区只活在内存里 —— **关窗即失**，而且超过 2000 行会裁掉**最旧的**那些（恰恰是 ComfyUI 启动参数、模型加载、自定义节点失败这类最该留的信息）。要事后排查，在程序目录建一个 `启动器配置.json`：

```json
{ "log_to_file": true }
```

开启后每次启动会在 `<程序目录>\logs\` 下新建 `运行-<日期>_<时分秒>.log`：

- **界面显示逻辑一行未改**，落盘是旁路；文件内容与界面显示**逐行一致**（同一行字符串、同样剥过 ANSI）。
- **文件不裁剪**：界面裁到 2000 行时，文件仍是全部行（实测 2500 行时界面 2000、文件 2500）。
- 崩溃最多丢最近 1 秒（flush 有 1 秒节流，但首行是立即落盘的）。
- 写不进去（目录只读 / 磁盘满）只会**静默降级为不落盘**，不影响界面。
- 打包成 exe 时，`logs/` 会建在 exe 所在目录旁边。

## 快速开始

```bash
python 视频方案启动器.py
```

1. 点顶栏「启动服务」，等状态变 **● 运行中**（首次加载约 15~60 秒，就绪后自动打开网页）
2. 点左导航到对应引擎（或直接点引擎标签），选输入（支持单个文件或整个文件夹）、设参数、点「运行放大」
3. 日志栏实时回传子进程输出，结束时打印 `rc` 与耗时，右下进度条同步

参考实测值（RTX 4070 Ti SUPER 16G）：

- FlashVSR：854×480 → 3416×1920（4x），2 分 39 秒
- SeedVR2：480p → 1080p（48 帧），约 23 分钟，音轨自动回接

## 覆盖默认路径

把 `启动器配置.example.json` 复制为 **`启动器配置.json`**，放在**程序同目录**（exe 则放 exe 旁边），只写需要改的键即可：

```json
{ "deploy_root": "D:\\my\\video-upscale-deploy" }
```

## 打包

```bash
pyinstaller VideoLauncher.spec
```

产物 `dist/VideoLauncher.exe`（单文件、无控制台窗口，约 13 MB；会跟随 `import ui_kit` / `import 运行时` 自动打包）。
**打包产物不入库，走 Releases 发行。**

> 打包前后注意：① 先 `taskkill /F /IM VideoLauncher.exe` 清残留（运行中的 exe 会锁住 `dist`，`--clean` 删不掉旧产物 → 构建中止却"看起来成功"，dist 里还是上一版）；② 打完核对**时间戳 + 体积**再冒烟。
> spec 里 **`upx=False`**：UPX 压缩过的单文件 exe 更像"自解压壳"，易被安全软件误报（表现就是"打开一闪就关"），收益远小于风险。
