# video-launcher · 视频方案启动器

> 一个窗口管住本地三套视频 AI 方案：**拉起 ComfyUI 服务 → 选输入 → 开跑**。
> 纯 Python 标准库实现（Tkinter，深色 UI 全自绘），零第三方依赖；源码可直接运行，也可打包成单文件 exe。

## 它解决什么

本地部署的视频放大 / 生成方案分散在多个目录、十几个 `.ps1` 里，每次都要手开终端、记参数、盯日志。本启动器把「启动服务 + 挑输入 + 传参 + 实时看日志」收进一个 GUI：

| 能力 | 干什么 | 背后调用 |
|---|---|---|
| FlashVSR 放大 | 视频放大（快） | `video-upscale-deploy/02-FlashVSR/批量放大.ps1` |
| SeedVR2 放大 | 视频放大（画质优先，音轨自动回接） | `video-upscale-deploy/03-SeedVR2/批量放大.ps1` |
| MiniMax H3 生成 | 文生视频 + 音画同出 | ComfyUI 服务 + 网页工作流（参数在网页里调） |

│ FlashVSR │ │ FlashVSR 放大     2x/3x/4x│ │   http://127.0.0.1 │← 地址

│ MiniMax  │ │ [       运行放大       ]  │ │ ────────────────  │
│ ──────── │ └──────────────────────────┘ │ 选择 / 加载工作流  │← 下拉 + 加载 .json
│ 设置      │                              │  · 节点详情 / 推送 │
│ 配置项…   │       （上排高度＝内容实测，    │                   │
│ 打开输入  │        剩余高度全给下排日志）   │                   │
├──────────┴──────────────────────────────┴──────────────────┤
│ 运行日志（横跨中栏 + 右栏，约 25 行）                          │
│  · 按类别着色（成功绿 / 工作流青 / 警告琥珀）                  │
│  ─────────────────────────────────────────────────────────  │
│  任务进度 65%                                                │
└──────────────────────────────────────────────────────────────┘

- **2×3 网格**：上排＝左（导航 + 设置）/ 中（引擎参数）/ 右（服务 + 工作流）；下排＝一整条**运行日志，横跨中栏 + 右栏**；左栏跨两行、通高
- **上排高度按内容实测、剩余全给日志**（v1.2.5）：上排不再抢高度的结果是日志文本区从 84px（约 4 行）变成 **310px（约 25 行）**
- **设置常驻左栏下方**（v1.2.3 起）：配置项只读展示 + 每项右侧「打开」；不再点导航到中栏单独刷出一页。窄栏下每项为「标签 + 值」两行
- **引擎切换只有左导航一个入口**（v1.2.3 去掉了中栏那排重复的切换按钮，v1.2.5 又去掉了「引擎 · 由左侧导航切换」小标题），点谁就重绘中栏引擎卡
- 窗口 1260×960（最小 1040×940），并按屏幕可用区夹住 —— 保证引擎卡与工作流卡的按钮都不落到折叠线以下，也不会比屏幕还高
- 配色：背景 `#15171c` / 卡片 `#232730` / 蓝 `#4a9eff` / 紫 `#b389f0` / 青 `#34d3b0`，圆角 12px 自绘卡片与柔和阴影
- 设计蓝本见分支 `ui-redesign` 的 `redesign/video_launcher_sidebar.html`
- 服务状态（圆点 / 「运行中」徽标 / 版本 / 显存）每 5 秒刷新；服务未运行时显存退回 `nvidia-smi` 读显卡
- 日志按类别着色（成功绿 / 工作流青 / 警告琥珀），并从输出里解析 `x/y` 或 `n%` 驱动右下进度条
- **子进程一律不弹黑窗**（v1.2.5）：exe 是无控制台程序，所有子进程都带 `CREATE_NO_WINDOW`，不会 5 秒闪一次黑窗
- **崩溃有据可查**（v1.2.5）：万一未捕获异常，会写一份 `崩溃日志.log` 到程序同目录（exe 则写在 exe 旁边）

## 环境要求

- Windows + Python **3.12+**（本机实测 3.13 / 3.14 打包）
- **零第三方依赖**：只用标准库（`tkinter` / `subprocess` / `threading` / `queue` / `urllib`）
- 需要已有一套本地部署（默认路径见下表），或用 `启动器配置.json` 指到你自己的路径

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `comfy_dir` | `C:\AI\ComfyUI` | ComfyUI 底座目录 |
| `comfy_py` | `C:\AI\ComfyUI\.venv\Scripts\python.exe` | 底座使用的解释器 |
| `deploy_root` | `C:\AI\video-upscale-deploy` | 批量放大脚本所在仓库 |
| `ffmpeg_dir` | `C:\AI\ffmpeg\bin` | 显式前置到子进程 PATH，不依赖注册表 |
| `input_dir` | `E:\VideoUpscale\input` | 素材目录 |
| `output_dir` | `E:\VideoUpscale\output` | 成品目录 |
| `comfy_url` | `http://127.0.0.1:8188` | ComfyUI 服务地址 |
| `log_dir` | `<程序目录>\logs` | 日志落盘目录（见「关于运行日志」） |
| `log_to_file` | 未设置（= 关闭） | 置 `true` 后把日志区内容同时写入 `log_dir` |


## 源码结构（v1.2.14 起为四文件）

| 文件 | 说明 |
|---|---|
| `视频方案启动器.py` | 配置 + 业务逻辑 + 界面装配（PyInstaller 入口；版本号常量 `APP_VER` 在这里） |
| `服务面板.py` | **App 的服务 mixin**（v1.2.14 拆出）：服务启停 / 重启 / 队列清理 / 批量任务等 15 个方法；与主程序共享同一个 `CONFIG` 字典 |
| `ui_kit.py` | 深色自绘控件库 + 设计令牌（含 `SettingsList` 设置项列表、`ask_text` 模态输入弹窗、`WorkflowDetail` 工作流详情）（**不 import 业务代码**） |
| `运行时.py` | 与界面无关的运行时支撑：子进程"不弹黑窗"标记 / 崩溃落盘 / 绕代理 HTTP / **日志行解析与清洗**（ANSI 剥离、进度、级别、着色分类）/ **日志落盘**（`LogFile`、`NoopLog`）/ **启动自检**（`probe_path`、`startup_lines`）/ **设置项读写与打开**（`config_items`、`save_config`、`open_path`）/ **工作流 API 图取用与 UI→API 转换**（`pick_api`、`load_api`、`read_workflow`、`apply_input`、`apply_patch`、`ui_to_api`）/ **工作流目录扫描**（`scan_workflows`）/ 内置工作流清单（**不 import 业务代码，也不 import tkinter**） |

> 按 `AGENTS.md`「按阈值拆分」：单文件逻辑行超过 pylint 默认上限（1000）时才拆。`ui_kit.py` 是 v1.2.0 抽的，`运行时.py` 是 v1.2.5 抽的，v1.2.6 把日志行解析也归了进去（当时主文件到 1001，拆完回到 986）；v1.2.8 的落盘、v1.2.9 的启动自检同样放 `运行时.py`；v1.2.10 又拆了一次（`WORKFLOWS` / 子进程环境 / 显存探测 / 打开目录 / 输入校验下沉到 `运行时.py`，设置区整块交给 `ui_kit.SettingsList`）；**v1.2.11 把工作流详情整块（~70 行）搬成 `ui_kit.WorkflowDetail`**；v1.2.12 下拉弹出化后主文件 953 / 1000；**v1.2.14 把服务启停 / 批量任务 15 个方法拆成 `服务面板.py`，主文件 899 / 1000（余量 101）**。依赖单向：`视频方案启动器.py` → `服务面板.py` → `ui_kit.py` / `运行时.py`。版本号在主文件的 `APP_VER` 常量（窗口标题会带它）。

## 关于运行日志（v1.2.6 实测口径，v1.2.8 加落盘）

日志区有三类来源，**只有本程序启动的服务才有日志可读**：

| 来源 | 日志区里长什么样 |
|---|---|
| 本程序自身 | `[服务] ...` / `[工作流] ...` / `[队列] ...` |
| **由本程序「启动服务」拉起的** ComfyUI | `[ComfyUI] ...`（stderr 已并进同一根管道，逐行实时） |
| 批量任务（PowerShell） | `════ ▶ <任务名>` 之间的输出 + 结束时的 `■ ... rc= / 用时` |

- **已经在外部（自己的终端 / 别的窗口）跑起来的 ComfyUI，日志不会出现在这里**：本程序探测到服务活着就直接返回，那些输出绑在别人的终端上，本程序没有句柄。想在日志区里看 ComfyUI 日志，就用「启动服务」让本程序把它拉起来。
- 显示前会做三件事：剥掉 ANSI 转义码（终端色彩码在 Tk 里会显示成方块）、按权限级别上色（`[ERROR]` 红 / `[WARNING]` 黄）、把行里的进度解析到进度条。日志区最多保留 2000 行，超出自动裁掉最旧的。

### 让日志"留得下来"：日志落盘（默认关闭）

日志区只活在内存里 —— **关窗即失**，而且超过 2000 行会裁掉**最旧的**那些（恰恰是 ComfyUI 启动参数、模型加载、自定义节点失败这类最该留的信息）。要事后排查，在程序目录建一个 `启动器配置.json`：

```json
{ "log_to_file": true }
```

开启后每次启动会在 `<程序目录>\logs\` 下新建 `运行-<日期>_<时分秒>.log`：

- **界面显示逻辑一行未改**，落盘是旁路；文件内容与界面显示**逐行一致**（同一行字符串、同样剥过 ANSI）。
- **文件不裁剪**：界面裁到 2000 行时，文件仍是全部行（实测 2500 行时界面 2000、文件 2500）。
- 崩溃最多丢最近 1 秒（flush 有 1 秒节流，但首行是立即落盘的）。
- 写不进去（目录只读 / 磁盘满）只会**静默降级为不落盘**，不影响界面。
- 打包成 exe 时，`logs/` 会建在 exe 所在目录旁边。

## 启动自检（v1.2.9）

启动时逐项**真实检测**（真的去读盘），而不是把路径打印出来。就绪打 ✅、缺失打 ⚠️ 并写明原因；左栏「设置」里每一项下面显示的就是这份实测结果（未就绪的整条转琥珀色）。

| 检查项 | 判到"能力级"而不是"目录在不在" |
|---|---|
| ComfyUI 目录 | 必须有 `main.py` —— 目录建了但没克隆完，算未就绪 |
| ComfyUI Python | 该解释器文件必须存在 |
| 部署脚本目录 | 必须有 `02-FlashVSR` / `03-SeedVR2` 两个引擎子目录 |
| ffmpeg 目录 | 必须有 `ffmpeg.exe`；若本目录没有、但系统 PATH 上另有一份，提示会写出那一份的路径（照着拷过来即可）。**提示不改变判定**，配置目录缺失仍算未就绪 |
| 输入 / 输出目录 | 必须存在 |

缺失原因是分开的，方便照做：**`未配置`**（值为空）/ **`路径不存在`** / **`缺 <具体项>`**。

## 改设置：不用再手编配置文件（v1.2.10）

左栏「设置」每一项后面都有两个入口：

- **打开** —— 目录用资源管理器打开；`ComfyUI Python` 这类文件会打开所在目录并**选中**它；`服务地址` 直接用浏览器打开。
- **修改** —— 点它，或者直接点下面的路径文字，会弹出输入框；目录项 / 文件项还带「浏览…」可以挑。保存（或回车）后**立即生效**，并写回程序同目录的「启动器配置.json」。

改完会连着做三件事：写盘 → 日志里记一行 `[设置] <项> = <新值>`，**紧跟该行的 ✅/⚠️ 检测结论** → 左栏整列刷新。所以路径填错**当场就能看见**，不必重启程序。

- 写盘是**合并写入**：只改你动过的那几项，文件里原有的其它键（包括备注用的 `_说明`）原样保留。
- 现有配置文件**读不动时会报错而不是覆盖** —— 宁可这次改不成，也不会把你手写的配置丢掉。
- 「服务地址」改完会同步更新服务卡上显示的地址。

## 界面布局（v1.2.12 收敛）

- **中栏（第 2 列）** = ComfyUI 服务卡（顶部，高度恒定）+ 引擎参数卡（自适应填满，内容超出就滚动）
- **右栏（第 3 列）** = 工作流卡（唯一卡片；高度按内容定死，选不同方案不会跳）
- **工作流下拉是弹出菜单**：选项浮在界面上方，展开 / 收起**不改变任何布局高度**
- 服务卡四个按钮**一行等大**（启动 / 打开网页 / 停止服务 / 停止队列任务）

## ComfyUI 工作流全量并入 + 备注名（v1.2.14）

- **启动时自动扫描 ComfyUI 的工作流目录**（`<ComfyUI 目录>\user\default\workflows\`），里面所有 `.json` 直接进下拉——你在 ComfyUI 网页里保存的工作流，重启启动器（或点「刷新」）就能看到，不用再逐个「加载 .json」。
- **这些图从"能选"变成"能推"**：ComfyUI 存的是 UI 格式，`/prompt` 只认 API 格式——此前直接推会报 `missing_node_type`。现在推送前自动转换（对齐前端 graphToPrompt 的规则），选中的瞬间后台就开始预热，推送不等。子图节点暂不支持（会提示在 ComfyUI 里展开后再存）。
- **备注名**：选一个本地工作流后，详情卡上点「备注」给它起个好记的名字（留空清除）。下拉和详情标题显示备注名，原名保留；备注存在 `启动器配置.json` 里，重开还在。
- 工作流卡顶部多了一个「刷新」：重扫目录 + 清转换缓存（ComfyUI 重启过、插件变了就用它）。

## 内置方案直接推 + 停止队列任务（v1.2.11）

**右栏工作流下拉里的内置方案，现在选中就能推送 / 入队**，不再只是说明书：

- FlashVSR 的两个方案绑定了部署脚本目录里的真实 API 图（`<部署脚本目录>\workflows\`），推送前自动做三件事：**按素材有没有音轨挑图**（挑错会在 ComfyUI 第一个节点就报错，判不出来一律按有音轨处理，宁可报错也不静默丢声）、**把图里的示例素材路径换成你界面上选的输入**、**按方案覆盖参数**（如「动画 4x」把 scale 改成 4）。日志里每一步都写明。
- **自己「加载 .json」的图也会进下拉菜单**，切走还能选回来；推送时同样会帮你换掉图里硬编码的素材路径。
- SeedVR2 与 MiniMax 方案暂无本地 API 图（H3 本来就在网页里搭），下拉选中后详情会指出图库位置。
- 服务卡上有**「停止队列任务」**按钮（与启动 / 停止服务同排等大）：打断正在跑的 + 清空排队中的（先读一次 `/queue`，队列本来就空会直说）。它只走 HTTP，**外部启动的 ComfyUI 也能用**。

## 外部启动的 ComfyUI 也能停 / 重启（v1.2.13）

「停止服务」和「重启服务」不再挑进程出身：

- 服务是**本程序拉起的** → 直接用句柄关闭（和以前一样）。
- 服务是**别处启动的**（自己开的终端、exe 升级前遗留的）→ 程序按命令行找到它的进程，结束进程树后照常重启。
- 找不到带配置目录的进程时，会列出命令行里带 `main.py` 的**疑似进程**（只列不杀）——确认是 ComfyUI 就手动结束，或把它的目录填进设置里的「ComfyUI 目录」再试。
- 服务没在跑时点「重启」= 直接启动。

## 快速开始

```bash
python 视频方案启动器.py
```

1. 点顶栏「启动服务」，等状态变 **● 运行中**（首次加载约 15~60 秒，就绪后自动打开网页）
2. 点左导航到对应引擎（或直接点引擎标签），选输入（支持单个文件或整个文件夹）、设参数、点「运行放大」
3. 日志栏实时回传子进程输出，结束时打印 `rc` 与耗时，右下进度条同步

参考实测值（RTX 4070 Ti SUPER 16G）：

- FlashVSR：854×480 → 3416×1920（4x），2 分 39 秒
- SeedVR2：480p → 1080p（48 帧），约 23 分钟，音轨自动回接

## 覆盖默认路径

把 `启动器配置.example.json` 复制为 **`启动器配置.json`**，放在**程序同目录**（exe 则放 exe 旁边），只写需要改的键即可：

```json
{ "deploy_root": "D:\\my\\video-upscale-deploy" }
```

> 更省事的办法是**直接在界面上改**（见「改设置」一节）—— 保存的就是这个文件，文件不存在时程序会自己建。手写只适合首次部署时一次性把几条路径都填好。

## 打包

```bash
pyinstaller VideoLauncher.spec
```

产物 `dist/VideoLauncher.exe`（单文件、无控制台窗口，约 13 MB；会跟随 `import ui_kit` / `import 运行时` 自动打包）。
**打包产物不入库，走 Releases 发行。**

> 打包前后注意：① 先 `taskkill /F /IM VideoLauncher.exe` 清残留（运行中的 exe 会锁住 `dist`，`--clean` 删不掉旧产物 → 构建中止却"看起来成功"，dist 里还是上一版）—— **你自己双击开着的那份也算数**（v1.2.10 实测：窗口还开着就打包，构建直接中止，`dist` 里仍是旧版）；② 打完核对**时间戳 + 体积**再冒烟。
> spec 里 **`upx=False`**：UPX 压缩过的单文件 exe 更像"自解压壳"，易被安全软件误报（表现就是"打开一闪就关"），收益远小于风险。
